# atlas-verify 0.1.1: dependency map

What the verifier package contains, what each file needs, where every line of it came from, and every outbound request it
can make. The function, host and file-type lists below are enforced by `test/lib/package-audit.js`: a new call, host or
file type fails the test until it is added there on purpose.

## 1. Files

The package is built from `packages/atlas-verify/manifest.json` (10 listed files, plus a generated `PACKAGE.json`). Every
entry names its source in this repository, its SHA-256 and its size; the build stops if any source differs from the lock.

| Package path | Source in the repository | Role | Lines |
|---|---|---|---|
| `verify.php` | `verifier-php/verify.php` | HTTP entry point (GET status, POST verdict) | 102 |
| `lib/atlas-verify.php` | `verifier-php/lib/atlas-verify.php` | trust configuration, document reading, verdict logic | 449 |
| `lib/atlas-verify-crypto.php` | `verifier-php/lib/atlas-verify-crypto.php` | base64url, DER conversion, P-256 verify, canonical JSON | 159 |
| `lib/atlas-verify-fetch.php` | `verifier-php/lib/atlas-verify-fetch.php` | bounded HTTPS GET (curl, stream fallback) | 72 |
| `config.example.php` | `verifier-php/config.example.php` | documented template; the operator copies it to `config.php` | |
| `.htaccess`, `lib/.htaccess` | `verifier-php/` | no directory listing, `config.php` and `lib/` not served | |
| `README.md`, `VERSION`, `LICENSE` | `verifier-php/`, repository root | documentation, version, licence | |
| `PACKAGE.json` | generated by the builder | per-file SHA-256 and size, read by `check-package.py` | |

Nothing else is in the archive. In particular there is no `config.php` (every install starts unconfigured), no key, no
state file, no image or script, no Composer or `vendor/` folder, and no module from the issuer, the studio, the demo
domains or any optional feature.

## 2. File-to-file requires

```
verify.php ──require──> lib/atlas-verify.php ──require──> lib/atlas-verify-crypto.php
     │                                         └─require──> lib/atlas-verify-fetch.php
     └──include──> config.php   (operator-supplied, __DIR__-relative, absent in the archive)
```

Every `require` is a literal `__DIR__`-relative path to a file inside the package; the audit resolves each one. The three
library files refuse to run when requested directly. All library code lives in the namespace `DomainAtlas\Verify`, so it
cannot collide with an issuer or any other Domain Atlas component installed on the same host.

## 3. PHP requirements

PHP 7.4 or newer (syntax is checked at token level for PHP 8-only constructs; see section 7 for what could not be run).
Extensions, all part of a default PHP build except the optional ones noted:

| Extension | Used for | Required |
|---|---|---|
| openssl | `openssl_verify` (P-256 / SHA-256 signature check) | yes; without it every credential answers `unavailable` |
| json | `json_decode`, `json_encode` | yes |
| curl | outbound HTTPS | one of curl or `allow_url_fopen` |
| pcre, date, hash, filter, standard, Core | parsing, timestamps, constant-time token compare, URL validation, string and array basics | yes (always present) |

Builtins called, by extension (the audit's allowlist, and the complete list):

- standard: abs, array_key_exists, array_keys, array_map, array_values, base64_decode, base64_encode, call_user_func, chr,
  chunk_split, count, file_get_contents, floor, gettype, header, http_response_code, implode, in_array, ini_get, ini_set,
  is_array, is_bool, is_callable, is_file, is_float, is_infinite, is_int, is_nan, is_object, is_string, ltrim, microtime, min,
  ord, parse_url, realpath, rtrim, sprintf, str_repeat, stream_context_create, strtolower, strtr, substr, trim, usort
- Core: defined, function_exists, get_object_vars, property_exists, strlen
- date: checkdate, gmdate, gmmktime
- curl: curl_close, curl_error, curl_exec, curl_getinfo, curl_init, curl_setopt_array
- hash: hash, hash_equals
- json: json_decode, json_encode
- filter: filter_var
- openssl: openssl_verify
- pcre: preg_match
- PHP 8.4 only, behind `function_exists()`: http_get_last_response_headers

Not called anywhere, and forbidden by the audit: every `openssl_*` function other than `openssl_verify` (so no signing,
no key generation, no key export), every `sodium_*` and `random_*` function, anything that writes or deletes a file,
anything that runs a program, `eval`, variable functions other than one local closure, database and raw socket functions.
The function `openssl_verify` takes the issuer's public key as a PEM string built from the 65-byte point; there is no
private key handling of any kind.

## 4. Inputs

| Input | From | Notes |
|---|---|---|
| `config.php` | the operator | `trustedIssuers` (required), `allowedOrigins`, `accessTokenSha256`, `maxBodyBytes`, `allowInsecureLoopback` (testing only) |
| HTTP request body | the caller | the credential (at most 256 KiB by default, 1 MiB at most) and an optional `expectIssuer` |
| `Authorization: Bearer` | the caller | only when `accessTokenSha256` is configured |

The issuers to trust come only from `config.php`. A request chooses among them by the domain the credential names; it
cannot add one, and `expectIssuer` can only narrow the choice.

## 5. Outbound requests: the complete list

At most three HTTPS GET requests per credential, each to the configured issuer origin:

1. `<origin>/.well-known/atlas-key.json` (read first; at most 256 KiB)
2. `<origin>/.well-known/atlas-revocations.json` (at most 4 MiB, 20,000 entries)
3. `<origin>/.well-known/atlas-suspensions.json` (at most 4 MiB, 20,000 entries)

Properties: GET only; HTTPS required (plain HTTP only for `localhost`/`127.0.0.1`/`[::1]` and only with
`allowInsecureLoopback`); redirects are not followed; certificates and host names are verified; 5 s connect and 10 s total
timeout; response size is capped while streaming; no cookies, no credentials, no data from the credential in the URL. The
tests run the verifier with a proxy and a canary server to show that URLs and domains inside credentials, and a hostile
`expectIssuer`, produce no request anywhere else.

No request goes to any site of this project. The package contains no host name other than the placeholders
`issuer.example`, `example.com`, `example.org` and `localhost`.

## 6. Where the code came from

Nothing was written as a substitute for existing working code where the existing code could be taken as it is.

| Package code | Source | How |
|---|---|---|
| `b64url_decode`, `raw_to_der_ecdsa_sig`, `der_int_encode`, `pem_wrap`, `ec_raw_point_to_pem`, `ecdsa_verify_raw`, `atlas_json_string`, the SPKI prefix constant | `issuer-php/lib/crypto.php` | verbatim, moved into the package namespace; the test compares each function body character for character |
| `canonicalize` | `issuer-php/lib/crypto.php` | adapted (section 6.1) |
| published-document semantics (key `validFrom`/`validUntil`, `revoked`, `suspended`, `expiresAt`, `onExpire`) | `issuer-php/lib/store.php`, `extension/wallet.js` (`readPublishedDoc`, `revocationVerdict`), `SPEC.md` §5 | behaviour reproduced; the test drives the real issuer and the package against each other |
| signed payload `{id, asset, owner, quantity, supersedes, issuedAt}` | `issuer-php/lib/bootstrap.php` (`asset_payload_of`), `SPEC.md` §5 | same field set |
| strict base64url decoding, trust supplied by server setup and never taken from the credential, optional key pin | `domain-atlas-next` `experiments/pinned-asset-signature-verifier.js` | same rules, in PHP |
| `domain-atlas-core` | nothing | a separate CBOR / chain protocol with no verifier for `domain-atlas-asset/1.0` |

### 6.1 The one adapted function

The issuer's `canonicalize` decodes JSON with `json_decode(..., true)`. PHP turns an empty object `{}` into an empty array
and then writes `[]`, while JavaScript writes `{}`, so a credential whose asset contains an empty object would verify in the
browser wallet and fail here. The package decodes with `json_decode(..., false)` and canonicalizes `stdClass` objects, which
keeps `{}`. It also sorts keys by UTF-16 code unit (what `Array.prototype.sort` does) instead of by bytes, and writes
floating-point numbers with the ECMAScript `Number::toString` rules (the issuer's text differs from JavaScript for
magnitudes below 1e-4 and at or above 1e17, and for integers beyond 2^53). For every document in the test corpus (about 1,500
random documents with unicode keys, empty containers and extreme numbers) the package output equals Node's byte for byte;
the reference PHP issuer agrees on every document without an empty object, a supplementary-plane key or an extreme number.

## 7. Evidence

`node test/verifier-package.js` (under a minute, no network beyond localhost) runs 217 checks against the archive, not the
source folder. `php test/verifier-php/matrix.php <dir>` runs 179 of those directly. Summary by area:

- build and reproducibility: two builds from different directories, time zones and locales are byte-identical; 20
  refusal cases for the builder; damage cases for the checker
- independent checker `tools/package/check-package.py`: re-hashes sources, parses the ZIP without a ZIP library, compares
  both SHA-256 files, rebuilds the archive and requires identical bytes
- content audit of the extracted archive (this document's lists)
- provenance of the copied crypto
- canonical-JSON parity against Node and the reference issuer
- the verdict matrix: every way each of the three documents can be missing, malformed, oversize or unreachable, tampering
  with every signed field, key rotation, pinning, expiry, suspension with `lift` and `finalize`, precedence between outcomes
- live credentials from a throw-away copy of `issuer-php`: anonymous issue, split (old credential revoked, both new ones
  verify), expiry, suspension and unsuspension, revocation; plus the issuer breaking its own published files while the
  verifier runs
- the fetch layer: redirects, size caps, non-HTTPS schemes, a server that never answers
- clean installations: only the manifest files exist after extraction, serving requests writes nothing, `open_basedir` and
  `allow_url_fopen=0`, no `php.ini`
- no runtime dependency on other sites: proxy and canary servers receive nothing, the issuer sees only GETs for its three
  documents

Added in the hardening follow-up, each also run from the built archive: `test/verifier-endpoint-abuse.js` (55 checks:
cost to the issuer per kind of request, oversize and malformed bodies, access token, methods, bounded upstream answers),
`test/verifier-protocol-limits.js` (11 checks: what the signature does not cover), and `test/verifier-private-config.js`
(9 checks: configuration kept outside the web root). Inputs, outbound requests and the function list in this document are
unchanged by them; 0.1.1 added one `preg_match` pattern and one `json_encode` check inside functions already listed.

Mutation checks were run by hand: a revocation failure turned into a pass, a signing function added, a hard-coded external
URL, and byte-order key sorting each fail the suite.

Not run, and not claimed: PHP 7.4 itself (the sandbox has PHP 8.3 only; the code is checked for 8-only syntax and
functions), Apache `.htaccess` enforcement (PHP's built-in server ignores it), and a real TLS issuer (the tests use
loopback HTTP behind `allowInsecureLoopback`; the HTTPS option set is exercised only by reading it).
