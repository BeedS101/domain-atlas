# World-drop render policy

A dropped item is drawn in the 3D (`gltf-mini-v1`) world from its asset's model, spinning
in place. Drop models are authored by whoever issued the asset and fetched from
anywhere, so one very heavy model (a 22 MB scan, say) can drop every visitor in the
world to a few frames per second. The renderer therefore checks a drop's model against a
small render budget before it uploads anything to the GPU, and draws a tiny generic
shape instead when the model is over budget or unusable.

Only the 3D representation changes. A drop keeps its id, position, asset, label,
"E - pick up" prompt and pickup call, and nothing about asset ownership, signing, the
drop/claim protocol or ordinary scene objects is touched.

## Selection order

For every drop the renderer tries, in order:

1. `asset.dropPreviewModel`, if the asset has one, loads and is within the budget;
2. `asset.model`, if it loads and is within the budget;
3. the generic fallback model (`extension/models/drop-fallback.glb`).

Until a choice is made, and for a drop whose asset has no model at all (or if even the
fallback cannot load), the drop shows the small amber glow marker it always did.

A refusal and a plain failure are told apart: a model that was refused on the budget
is a `policy` fallback, one that was missing, corrupt or unparseable is a `failed`
fallback. Both draw the same shape; the HUD counts them separately.

## What the budget measures

Defaults, used for every key a domain does not set:

| Key | Default | Meaning |
| --- | --- | --- |
| `maxModelBytes` | 1,000,000 | Size of the downloaded model (decoded, after any HTTP compression). |
| `maxTriangles` | 50,000 | Triangles in the drawn model (a node that instances a mesh counts each time). |
| `maxTextureSize` | 1024 | Largest texture side, in pixels. |
| `maxTextures` | 4 | Distinct textures. |
| `maxPrimitives` | 32 | Draw calls (primitives) per model. |

Primitives stand in for "materials": each primitive is a draw call, which is what costs
time per frame. The defaults are conservative; the bundled demo models are all far
below them. Each value must be a finite number of at least 1 (fractions are rounded
down). An invalid value is ignored with a one-time console warning and the default is
used for that key.

## Configuring it

`worldDropPolicy` follows the domain-default/world-override convention (SPEC.md section
3.4.1):

```json
{
  "domain": "example.com",
  "worldDropPolicy": { "maxModelBytes": 2000000, "maxTextureSize": 2048 },
  "worlds": [
    { "id": "lobby", "...": "...",
      "policy": { "worldDropPolicy": { "maxModelBytes": 500000 } } }
  ]
}
```

- A top-level `worldDropPolicy` applies to every world of the domain.
- A world's `policy.worldDropPolicy`, when present, wins outright. It is not merged with
  the domain value: keys it leaves out use the built-in defaults, not the domain's.
- With neither, the built-in defaults apply.

The policy is read when a world is entered. It is a client-side render budget and does
not need any server change.

## What the fallback is

`extension/models/drop-fallback.glb` is an amber 8-triangle gem, 1.5 KB, one material
and no texture, generated by `tools/make-drop-fallback-model.js` (`--check` verifies the
committed file is current). It is loaded once per world entry and every fallback drop
shares the same GPU buffers, so 30 refused drops cost the same as one. A refused model
is never kept in the model cache; only its URL is remembered for the session, so the next
drop of the same URL is not downloaded again.

## Byte limit enforcement

The size is enforced in layers; the first is only a shortcut:

1. `Content-Length`, when present and above the limit: the request is cancelled before
   any body is read.
2. Streamed bytes: the body is read as a stream and cancelled as soon as the running
   total passes the limit, whatever the headers said. This covers a missing length
   (chunked transfer) and a length that understates the body (for example a gzip response
   whose compressed length is small and whose decoded size is not): the count is of
   decoded bytes.
3. A copy already in the local model cache is checked by its size.
4. If the environment gives no streaming reader, the body can only be measured after it
   has been read; the limit still decides whether it is used.

Limitations: a model is refused as soon as the limit is passed, so up to the limit
(plus one chunk) is downloaded for a stream that never states its length. The triangle
and primitive limits are checked from the glTF JSON before any geometry is read, so an
instanced model is stopped cheaply, but a model within the byte limit still costs some CPU
to parse. Texture size is read from the PNG/JPEG header, before decoding; other image
types are not accepted by the renderer anyway.

## Optional `asset.dropPreviewModel`

An asset may carry `dropPreviewModel`, an absolute URL of a lighter model used only for
the drop (SPEC.md section 5). It is signed only if the issuer includes it. It is the one
schema addition; nothing else about the credential changes.

- `issuer-server`: add `dropPreviewModel` to the class's `ASSET_CATALOG` entry.
- `issuer-php`: add `dropPreviewModelPath` (a path on the domain) to the class's catalog
  entry; it is published as `https://<domain><path>`.

Existing credentials and drops without it behave as before.

## Recommendations for asset authors

- The full `model` can be rich: it is used in previews and when it fits the budget.
- Give a drop its own light `dropPreviewModel` (a few thousand triangles, one small
  texture, well under 1 MB) if the full model is heavy.
- Do not rely on a multi-megabyte model for something that spins on the floor of a
  shared room.
- Keep textures at 1024 px or less and share them between materials.

## HUD

With the F3 HUD open and at least one drop in the world, a DROPS section shows:
Rendered (and how many of them are previews), Fallback, Rejected GLB (the fallbacks
that were refused on the budget), plus Pending and Marker only when non-zero. The numbers
come from the same state the renderer draws from; nothing is counted per frame.

## Files

- `extension/gltf-mini.js`: the guarded loader, the policy and drop selection.
- `extension/viewer.js`: reads `worldDropPolicy`, passes the preview URL and the fallback URL.
- `extension/gltf-mini-hud.js`: the DROPS section.
- `extension/models/drop-fallback.glb`, `tools/make-drop-fallback-model.js`.
- `issuer-server/server.js`, `issuer-php/lib/store.php`: pass `dropPreviewModel` through.

## Tests

- `test/manual-3d-drop-guard-unit.js`: policy defaults and validation, image sizes, model
  cost and each limit, the fallback model, bundled models within the defaults.
- `test/manual-3d-drop-guard-world.js`: in the real viewer with a misbehaving model
  server: preview preference, oversized full and preview models, corrupt, missing, huge
  texture, chunked and gzip-bomb responses, pickup of fallback drops, shared GPU
  resources, no cache retention, HUD counters and the policy override rules.
