Try it yourself: one complete 2-of-2 transfer

You get a private test session with 100.00 DEMO for Alice and 0.00 for Bob. Start a transfer, then ask each domain to approve it: each one fetches the same transaction, checks it against its own rules and signs with its own server-side key. Only when both have signed does the transfer execute and a signed receipt appear. No wallet, no administrator token, no real money.

This is an approving domain.     What this proves, and what it does not. One domain alone can never execute the transfer; each domain signs with its own key and verifies the other's signature against a public key it pinned in its own configuration. A single settlement authority holds the demo balances and executes, so this is not atomic settlement across two independent ledgers; that needs a separate prepare/commit/recovery protocol.
    
  
    Failure cases (forged signature, wrong transaction, modified amount, duplicate approval, duplicate execution, insufficient balance, unavailable domain, restart, expiry) are exercised by the automated tests test/manual-txlab-php.js and test/manual-txlab-public-php.js, not by controls on this public page. Public sessions are limited, rate-limited and expire; the public test mode can never reset state, mint balances or sign arbitrary data.
