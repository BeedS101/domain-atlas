Configure a standalone credential verifier

This assistant generates configuration files in your browser. It does not upload files, fetch code, contact issuers, or change your server. No wallet, issuer, Core or Chainblock installation is required.

1. Choose who to trust

Only list domains you explicitly trust. Use domain origins, not URLs with paths. A verifier never learns new trusted issuers from a credential. Replace ACCOUNT with your hosting account name. Create the directory yourself outside public_html. The wizard cannot verify your server's filesystem layout.

2. Save the two files

The private file contains issuer configuration. The public stub contains only a PHP require path, and must remain protected from source disclosure.

3. Install manually on an isolated PHP test site

  1. Build the pinned atlas-verify-0.1.1.zip using the repository package builder and verify its SHA-256/checksums. Do not download an unpinned executable archive.
  2. Extract the verifier package into your intended atlas-verify/ web directory. Do not replace existing issuer files.
  3. Create the private directory outside the document root (mode 0700). Put verify-config.php there (mode 0600 or 0400). Upload config.php into the verifier directory, beside verify.php.
  4. Confirm Apache denies direct access to config.php and lib/, or configure equivalent rules on other web servers. Restrict public access to verify.php with an access token, proxy protection and rate limits before exposing it broadly.
  5. Open https://your-test-site.example/atlas-verify/verify.php. Require "configured": true, then POST a known valid and a revoked credential to check actual issuer communication and refusal behavior.

Safety: this is an evaluation/setup helper, not a one-click installer or a production security audit. The repository is currently All Rights Reserved; publishing it does not authorize third-party redistribution or deployment.

Runs fully offline. Nothing you enter is uploaded or stored by this assistant.
